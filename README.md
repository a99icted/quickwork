# QuickWork

Демонстрационный pet-проект сервиса разовых рабочих смен. Соискатель ищет смены и отправляет отклики, работодатель публикует смены и рассматривает кандидатов.

**Это демоверсия для портфолио.** Интерфейс на русском языке, города и валюта. Платежей, чата и загрузки документов нет.

## Возможности

- Каталог смен с поиском, фильтрами, сортировкой и избранным.
- Регистрация, вход, профиль и отслеживание статусов откликов.
- Компания внутри личного аккаунта: публикация и редактирование смен, одобрение и отклонение кандидатов.
- Админка для управления городами, категориями и условиями работы.
- JWT-авторизация с обновлением access-токенов через refresh-cookie и отзывом refresh-сессии при выходе.
- Адаптивный интерфейс для компьютеров и телефонов.

## Стек

**Backend:** Python, FastAPI, SQLAlchemy 2, SQLite / aiosqlite, Pydantic, PyJWT, Argon2.  
**Frontend:** JavaScript, React 19, React Router 7, Vite.

## Локальный запуск

Нужны **Python 3.12+** и **Node.js 22.12+**. Команды ниже — для **Windows PowerShell**, из корня репозитория. Отдельный сервер БД не требуется.

### 1. Установить зависимости и настроить окружение

```powershell
python -m venv venv
.\venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item server/.env.example server/.env
npm --prefix frontend ci
```

Если `server/.env` уже существует, сохраните свои настройки. Сгенерируйте секрет:

```powershell
.\venv\Scripts\python.exe -c "import secrets; print(secrets.token_urlsafe(48))"
```

Запишите результат в `JWT_SECRET_KEY` в `server/.env` вместо заглушки. Остальные настройки подходят для локального запуска.

### 2. Собрать интерфейс и запустить сервер

```powershell
npm --prefix frontend run build
cd server
..\venv\Scripts\python.exe src/run.py
..\venv\Scripts\python.exe -m uvicorn main:app --app-dir src --host 127.0.0.1 --port 8000
```

Приложение: [http://127.0.0.1:8000](http://127.0.0.1:8000).  
Документация API: [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs).

SQLite-база создаётся автоматически; `run.py` добавляет категории и условия работы. При первом запуске пользователей, городов и смен нет. Миграций нет, повторный запуск сохраняет данные. Для отдельной пустой базы задайте новое `DB_NAME` в `server/.env`.

### 3. Проверить сценарии демо

1. Зарегистрируйте аккаунт через интерфейс.
2. В другом терминале, из корня репозитория, назначьте ему права администратора:

   ```powershell
   cd server
   ..\venv\Scripts\python.exe src/manage_admin.py USERNAME
   ```

   Замените `USERNAME` на свой логин. Обновите страницу, откройте `/admin` и добавьте город.
3. Создайте компанию в своём аккаунте и опубликуйте смену.
4. Зарегистрируйте второй аккаунт в другом браузере или приватном окне и отправьте отклик. В аккаунте компании измените его статус; обновите страницу соискателя, чтобы увидеть решение.

## Проверки

Для запуска приложения `requirements-dev.txt` не нужен. Он добавляет `httpx` для серверных интеграционных тестов.

Команды из корня репозитория:

```powershell
.\venv\Scripts\python.exe -m pip install -r requirements-dev.txt
npm --prefix frontend run lint
npm --prefix frontend test
.\venv\Scripts\python.exe -m unittest discover -s server/tests -v
```

Серверные тесты используют отдельную временную БД. Проверяются авторизация и refresh-сессии, права доступа, компании, смены, отклики и справочники. Клиентские тесты проверяют восстановление и обновление сессии, обработку ошибок и выход.

Подробнее о токенах и настройках авторизации: [docs/authentication.md](docs/authentication.md).
